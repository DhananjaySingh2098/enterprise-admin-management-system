# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] — 2026-09-23

First complete release: the whole application built over seven phases, from foundation to a containerised,
tested release. The sections below group everything that reached this version; the phase each item came from is
noted for traceability.

### Added

**Foundation (Phase 1)**

- Spring Boot 4.1 / Java 21 backend with a layered package structure and the Maven Wrapper.
- Angular 22 single-page application (standalone components, signals, zoneless) with design tokens for light and
  dark themes, a dev proxy and an API service foundation.
- MySQL 8.4 with Flyway-owned schema; Hibernate only validates it.
- Health endpoints `GET /api/health` (liveness) and `GET /api/health/db` (database reachability).
- Architecture, security, design-system and phase documentation.

**Authentication and access control (Phase 2)**

- Sign-in, refresh, sign-out and `GET /api/auth/me`, with JWT access tokens (HS256, 15 minutes, minimal claims).
- Rotating refresh tokens: 256-bit values stored only as SHA-256 hashes, family reuse detection, a 7-day token TTL
  inside a 30-day absolute session, delivered as an `HttpOnly`, `SameSite=Strict` cookie scoped to `/api/auth`.
- Roles `ADMIN`, `MANAGER` and `USER`, enforced deny-by-default in the filter chain and with `@PreAuthorize`.
- Initial ADMIN bootstrap from `ADMIN_EMAIL`/`ADMIN_PASSWORD`, only while no ADMIN exists.
- BCrypt (cost 12) password hashing and a 12-character to 72-byte password policy.
- Login-abuse protection: bounded, exponentially growing lockouts per account and per IP.
- Angular login page, in-memory token storage, a refresh-coordinating interceptor, route guards and session restore.

**Administration and records (Phase 3)**

- ADMIN user administration: paged, searched, filtered and sorted lists; create, edit, role replacement and
  enable/disable (disabling revokes sessions); safeguards against self-disable, self-demotion and removing the last
  active ADMIN.
- Departments (deactivated, never deleted) and employees, both with server-side search, filters, allowlisted sorting,
  paging and optimistic locking (`409 STALE_VERSION`).
- Self-service profile, and a password change that signs out every other session.
- A premium application shell: role-aware navigation, page headers, drawers, confirm dialogs, mobile card tables and
  toasts, with motion that honours reduced-motion preferences.

**Dashboard and analytics (Phase 4)**

- Read-only `/api/dashboard/*` aggregates for ADMIN and MANAGER: summary, headcount by department, status breakdown,
  a continuous hiring trend (1–24 months), recent hires, and ADMIN-only account analytics. USER receives 403.
- Every figure is computed live from real rows by database aggregation, using existing indexes; nothing is estimated
  or invented.
- Dashboard with KPI cards, department bars, a status donut, a hiring-trend chart with its data table, recent hires,
  onboarding empty states, and a personal workspace for USER.
- Theme system: System/Light/Dark across the Aurora, Obsidian, Pearl, Midnight and Emerald presets, persisted
  locally and applied before first paint.

**Audit, notifications and settings (Phase 5)**

- Append-only audit trail of sign-ins, failures, sign-outs, token-reuse revocations and every user, employee,
  department and settings change, written in the same transaction as the change and doubly redacted. ADMIN-only
  Audit Logs API and page with filters, search, date range and a detail drawer.
- `X-Request-Id` on every response, in every log line, in audit events and in error bodies.
- In-app notifications generated by real account and record changes, with a header bell and a timeline page.
- Per-user appearance preferences (mode, preset, density) synced to the account without a flash of the wrong theme.
- ADMIN organization settings: organization name and the dashboard's recent-hire window (1–365 days).

**Release engineering (Phase 7)**

- Production images: a multi-stage backend build (Temurin 21, layered extraction, non-root uid 10001, healthcheck,
  container-aware JVM) and a multi-stage frontend build served by unprivileged nginx (uid 101) with a read-only root
  filesystem.
- `docker-compose.prod.yml`: frontend, backend, a one-shot migration job and MySQL on an internal network, with only
  the frontend publishing a port, a named data volume, and healthchecks on every long-running service.
- Docker secrets for all five credentials, read through Spring's `configtree`; nothing secret in images,
  environment files or build arguments. `scripts/generate-secrets.sh` creates them.
- nginx serves the SPA with the approved security headers and CSP, SPA fallback, gzip, immutable caching for hashed
  assets, `no-cache` for `index.html`, and reverse-proxies `/api` with forwarded headers it sets itself.
- `scripts/smoke-test.sh`: eight groups of end-to-end checks against a running stack through its public URL.
- GitHub Actions CI on pull requests and pushes to `main`: backend tests and SpotBugs/FindSecBugs, OSV and
  `npm audit` dependency scans, frontend tests/build/CSP checks on Node 22 and 24, a redacted gitleaks secret scan,
  Playwright end-to-end tests, and a container job that builds the images, starts the stack and smoke-tests it.
- Documentation: [DEPLOYMENT.md](docs/DEPLOYMENT.md), [RUNBOOK.md](docs/RUNBOOK.md), `.env.production.example`,
  and this changelog.

### Changed

- **Migrations moved out of the application** (Phase 7): the production backend runs with `FLYWAY_ENABLED=false`
  and only the runtime database account; a dedicated one-shot `migrate` container applies Flyway and the runtime
  grants, so the long-running service never holds DDL privileges.
- **One source of truth for the Content-Security-Policy** (Phase 7): `frontend/security-headers.json` generates the
  dev-server headers and the nginx snippet, and `npm run check:csp` fails the build if the policy, the boot-script
  hash, the nginx configuration or the built output drift apart.
- **Component styles moved to the global stylesheet** (Phase 6) so the SPA needs no `style-src 'unsafe-inline'`.
- **The recent-hire window became an organization setting** (Phase 5), replacing a hard-coded 30 days.
- **MySQL shutdown grace period raised to 60 s** (Phase 7): the 10 s default ended in SIGKILL (exit 137) before
  InnoDB had flushed.
- `.env.example` reorganised into sections with placeholders only, and every supported variable documented.

### Security

- **Headers and CSP** (Phase 6): a lock-down CSP for API responses; the SPA policy uses `script-src 'self'` plus the
  boot script's SHA-256 and `style-src 'self'`, with no `unsafe-inline`, `unsafe-eval` or wildcards. Framing denied,
  `no-referrer`, `nosniff`, Permissions-Policy and COOP/CORP. HSTS is sent only over HTTPS.
- **Rate limiting** (Phase 6): per-IP, per-account and per-user policies in a MySQL-backed store shared by every
  instance; reads are never limited; `429 RATE_LIMITED` with `Retry-After` and no information disclosure.
- **Least-privilege database accounts** (Phase 6, enforced by default in Phase 7): separate migration and runtime
  accounts, per-table grants re-applied after every migration, `audit_logs` restricted to SELECT and INSERT, and a
  startup probe that refuses to run if the runtime account can modify audit rows.
- **Session robustness** (Phase 6): recovery from an aborted refresh (`replaced_by_id`, `SUPERSEDED`), one bounded
  restore retry, and transient failures never signing a user out.
- **Authorization** (Phase 6): URL role rules mirroring `@PreAuthorize` so 403 is returned before request parsing,
  a full endpoint × role matrix test, and rejection of unknown JSON fields (mass-assignment defence).
- **Proxy trust** (Phase 7): nginx overwrites `X-Forwarded-For`, `X-Forwarded-Host` and `Forwarded`; a client-supplied
  `X-Forwarded-Proto` is honoured only when `NGINX_TRUST_FORWARDED_PROTO=on`, so HSTS and cookie flags cannot be
  poisoned by a spoofed header.
- **Fail-closed configuration** (Phase 7, verified): the backend refuses to start on a missing or too-short
  `JWT_SECRET`, a wildcard in `ALLOWED_ORIGINS`, an unknown rate-limit store, wrong database credentials or an
  over-privileged database account — each with a single clear message and no secret values in the logs.
- **Supply chain**: OSV scanning of every resolved Maven dependency, `npm audit` gates, SpotBugs with FindSecBugs
  and documented exclusions, and a gitleaks secret scan with narrowly scoped fixture allowlists.
- Container hardening: non-root users, no build tooling, shells or source in runtime images, no source maps shipped,
  a read-only root filesystem for nginx, and an internal network with no host or outbound access for the backend and
  database.

### Fixed

- Role checkboxes were invisible in the user dialog because of a CSS class collision introduced in Phase 5 (Phase 6).
- Badge contrast fell below WCAG AA (Phase 6).
- An appearance change made just before closing a tab could be lost inside the save debounce; pending saves are now
  flushed with a keepalive request and reconciled by timestamp (Phase 6).
- The recent-hires table widened the page on small screens (Phase 6).
- A refresh whose response was lost during a reload signed the user out (Phase 6).
- Validation ran before authorization on some endpoints, disclosing field-level detail to unauthorised callers
  (Phase 6).
- A `LazyInitializationException` when auditing sign-out (Phase 5).
- Embedded Tomcat pinned to 11.0.26 to clear known CVEs (Phase 6).
